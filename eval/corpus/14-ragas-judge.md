# RAGAS 与 LLM-as-judge 评测

检索指标（Recall、nDCG）只能评价"检索环节"，无法回答"最终答案好不好"。而答案质量恰恰是用户唯一能感知的东西。评价答案需要新的方法。

## 为什么答案评测很难

传统 NLP 用 BLEU、ROUGE 这类指标对比生成文本与参考答案的 n-gram 重叠。但它们在 RAG 场景下基本失效：

- **语义等价但措辞不同**：标准答案是"O(n log n)"，模型答"线性对数时间复杂度"，n-gram 重叠几乎为零，但答案完全正确。
- **答案不唯一**：同一问题的合理表述方式可以有很多种，参考答案只是其中一种。
- **无法评估忠实度**：BLEU 只能对比答案与参考答案，无法判断答案是否**忠于上下文**——而防幻觉恰恰需要检查后者。

## RAGAS 的核心指标

RAGAS（Retrieval Augmented Generation Assessment）是专为 RAG 设计的评测框架，定义了四个关键指标，分别对应链路的不同环节。

**1. Faithfulness（忠实度）**

衡量答案是否完全由检索到的上下文支撑。做法是把答案拆解成若干独立论断，逐条验证能否从上下文中推出：

    忠实度 = 可被上下文支撑的论断数 / 答案总论断数

这是**防幻觉的核心指标**。它不关心答案对不对（那是 correctness 的事），只关心答案有没有超出给定材料——一个"忠实但答非所问"的答案在业务上可能是无用的，但至少它没有编造。

**2. Answer Relevancy（答案相关性）**

衡量答案是否切题。做法通常是让模型根据答案反推出"这个答案可能在回答什么问题"，再计算反推问题与原问题的相似度。如果答案跑题，反推出来的问题会与原问题偏离。

这个指标能捕捉一类常见失败：答案本身流畅且忠实于上下文，但答的是另一个问题（往往因为检索到的片段偏离了用户意图）。

**3. Context Precision（上下文精度）**

衡量检索到的上下文中，有多少是真正有助于回答问题的，以及有用的部分是否排在前面。它同时考虑了相关性和排序位置。

**4. Context Recall（上下文召回）**

衡量标准答案中的信息有多少能在检索上下文中找到。这个指标需要一个参考答案（ground truth）作为基准。

它是最能定位问题的指标：**Context Recall 低说明检索漏了**，此时应该去优化切片、embedding 或 top_k；Context Recall 高但 Faithfulness 低，说明检索没问题而生成环节有问题，应该去调提示词或换模型。

## LLM-as-judge 的方法与陷阱

上述指标大多无法用规则实现，需要另一个大模型充当裁判，这就是 LLM-as-judge。

**基本做法**：把问题、上下文、答案（有时还有参考答案）按固定模板组织，要求裁判模型输出结构化评分和理由。关键是**要求给出理由**——只输出分数的裁判结果无法审计，无法判断评分是否可靠。

**已知偏差**，使用时必须警惕：

1. **位置偏差**：在成对比较中，裁判倾向于选择排在前面的选项。缓解方法是交换顺序各评一次，取平均。
2. **长度偏差**：更长的答案往往得分更高，即使信息量相同。
3. **自我偏好**：裁判模型倾向于给同族模型生成的答案更高分。用 GPT 系模型评 GPT 系答案会有系统性偏高。
4. **分数聚集**：裁判模型倾向给出 0.8 到 1.0 之间的分数，区分度不足。缓解方法是要求给出离散等级（如 1 到 5）而非连续分数，或提供评分锚点示例。

**可靠性验证**：一个好的实践是人工标注一小批样本（如 30 条）作为金标准，测量裁判模型与人工判断的一致率。如果一致率低于 80%，说明裁判提示词或维度定义需要修订，此时报出的指标不具备说服力。

## 规则指标与裁判模型互补

LLM-as-judge 有 API 成本、有速率限制、结果不完全可复现（同一输入多次调用可能给出不同分数）。因此务实的方案是两者并用：

- **规则指标**（关键词覆盖率、引用编号是否真实存在、答案长度）负责**可复现的底线**。它们不完美，但完全确定、零成本、可进 CI。它们的作用是**强否决**：关键词覆盖率低，答案几乎肯定是错的。
- **裁判模型**负责**语义层面的判断**，提供更接近人类评价的质量信号。

在资源受限或需要离线复现的场景，规则指标是唯一可行的选择；在有条件时，两者搭配能同时得到"稳定基线"和"质量上限"两个视角。

## 评测集设计要点

无论用哪种方法，评测集的质量决定了评测结论的可信度。一份好的评测集应包含：

- **难度分层**：简单（答案在单个片段中直述）、中等（需要综合多个片段）、困难（需要跨文档推理）。
- **类型覆盖**：事实型（"X 是什么"）、比较型（"A 和 B 的区别"）、数值型（"参数默认值是多少"）。
- **无答案样本**：考察拒答能力，这类样本必须有但常被忽略。
- **相近干扰项**：知识库中存在主题相近但内容不同的文档，用于检验检索的区分能力。

最后一点尤其重要：如果语料里每篇文档主题都截然不同，检索任务会异常简单，所有后端都能拿高分，评测就失去了区分度。
