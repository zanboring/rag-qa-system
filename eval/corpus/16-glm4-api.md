# 智谱 GLM-4 API 接入

智谱 AI 的 GLM-4 系列是国产大模型 API 中较常用的选择，接口协议与 OpenAI 高度兼容，接入成本低。

## 接口与认证

对话接口：

    POST https://open.bigmodel.cn/api/paas/v4/chat/completions
    Authorization: Bearer <API_KEY>
    Content-Type: application/json

请求体与 OpenAI 格式一致：

    {
      "model": "glm-4-flash",
      "messages": [
        {"role": "system", "content": "系统指令"},
        {"role": "user", "content": "用户问题"}
      ]
    }

响应中答案位于 `choices[0].message.content`。

Embedding 接口：

    POST https://open.bigmodel.cn/api/paas/v4/embeddings
    {"model": "embedding-3", "input": "待向量化文本"}

向量位于 `data[0].embedding`。

## 模型选型

GLM-4 系列按能力与价格分层：

- **glm-4-flash**：轻量版本，响应快、价格低，适合高并发或对成本敏感的场景。用于 RAG 的常规问答通常已足够。
- **glm-4-plus / glm-4**：能力更强，适合需要复杂推理、长文档理解的任务。
- **glm-4-long**：面向超长上下文，适合把整篇文档直接塞进提示词的场景。

RAG 场景的选择建议是：**先用 flash 版本建立基线**，评测确认生成环节是瓶颈后再升级模型。因为如果检索质量不达标，升级生成模型对最终效果的改善非常有限。

## 工程实践要点

**1. 复用 HTTP 连接**

每次请求都新建客户端会导致反复的 TCP 握手与 TLS 协商，在高频调用下开销显著。应当复用同一个 `httpx.AsyncClient` 实例：

    self._client = httpx.AsyncClient(timeout=60)

同时要注意客户端需要在使用完毕后关闭（`await client.aclose()`），否则连接池不会被释放。在 FastAPI 的 lifespan 钩子里做统一关闭是常见做法。

**2. 超时设置**

大模型推理耗时波动较大，默认超时（通常 5 秒）极易触发。建议对话接口设置 60 到 120 秒超时。但也不要设置过长——超时过长会让慢请求堆积，在高并发下引发雪崩。合理的做法是设置中等超时（如 60 秒）配合有限次数的重试。

**3. 速率限制与重试**

云端 API 有 QPS 和并发限制。批量调用时应当：

- 控制并发数（如用信号量限制在 5 到 10 并发）
- 对 429（限流）和 5xx（服务端错误）做指数退避重试
- 对 4xx（请求错误，如参数非法、余额不足）不要重试，直接失败

区分错误类型很重要——对不可重试的错误反复重试只会浪费配额和时间。

**4. 密钥管理**

API Key 绝不能硬编码进代码提交到仓库。正确做法是：

- 从环境变量读取
- `.env` 文件加入 `.gitignore`
- 缺失时给出明确报错，而不是静默降级为一个错误的默认值

配置层应当在启动时就校验必需的环境变量，让配置错误在启动阶段暴露，而不是等到第一次请求才失败。

## 与本地模型的对比

| 维度 | GLM-4 云端 | Ollama 本地 |
| --- | --- | --- |
| 效果 | 强，指令遵循稳定 | 受模型规模限制 |
| 数据合规 | 数据出网 | 数据不出本地 |
| 成本 | 按 token 计费 | 一次性硬件投入 |
| 延迟 | 受网络与服务端影响 | 本地推理，无网络开销 |
| 运维 | 无 | 需自建服务与模型管理 |
| 可用性 | 依赖外部服务 | 完全自主可控 |

选择的关键在于**数据合规要求**和**质量要求**孰先。企业内部文档场景下，合规往往是不可协商的硬约束，此时本地模型是唯一选项；对质量要求高且数据可出网的场景，云端 API 的综合成本（含运维人力）通常更低。

一种常见的折中架构是**双后端可切换**：通过环境变量控制使用哪一路，开发调试和评测阶段用本地模型（零成本、可反复跑），线上服务用云端模型（质量优先）。这样既控制了评测成本，又保证线上质量。
