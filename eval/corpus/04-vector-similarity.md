# 余弦相似度、点积与欧氏距离

向量检索的核心是"度量两个向量有多接近"。常用的三种度量各有适用条件，选错会导致排序结果失真，甚至让相似度数值失去可比性。

## 余弦相似度

余弦相似度衡量两个向量方向的夹角，公式为两向量点积除以两者模长之积：

    cosine(a, b) = (a · b) / (||a|| × ||b||)

取值范围是 -1 到 1。值为 1 表示方向完全一致，0 表示正交无关，-1 表示方向完全相反。它只关心方向，不关心长度，因此对文本长度差异不敏感——这正是文本检索通常偏好它的原因。

## 点积

点积就是对应维度相乘再求和，公式为：

    dot(a, b) = Σ aᵢ × bᵢ

点积同时受方向和模长影响。当两个向量都已做 L2 归一化（模长均为 1）时，分母变成 1，**点积与余弦相似度完全等价**。这就是为什么实践中会先把 embedding 归一化：归一化后可以用计算更快的点积替代余弦，且能直接使用针对内积优化的索引结构（如 FAISS 的 IndexFlatIP）。

## 欧氏距离

欧氏距离是向量空间中的直线距离：

    L2(a, b) = √(Σ (aᵢ - bᵢ)²)

值越小越相似，方向与相似度相反。它与余弦相似度的关系是：

    ||a - b||² = ||a||² + ||b||² - 2(a · b)

当两个向量都是单位向量时，该式简化为 ||a - b||² = 2 - 2·cos(a, b)。这说明归一化之后，欧氏距离与余弦相似度是**单调等价**的：距离越小，相似度越高，排序结果完全一致。

## 归一化为什么重要

上面的等价关系只在向量归一化后成立。如果向量未归一化就用欧氏距离排序，结果会被向量模长主导——长文档的向量模长通常更大，会莫名其妙地排到前面，即使它的语义与查询并不相关。

同样要注意的是，**距离值不能直接当相似度用**。常见的错误写法是用 `1 - L2距离` 当作相似度分数。当向量归一化时，L2 距离的范围是 0 到 2，`1 - dist` 的取值范围会落到 -1 到 1，但它的数值大小与余弦相似度并不相等（例如 L2 = 0.5 对应 cos ≈ 0.875，而 `1 - 0.5 = 0.5`），这会带来两个后果：

1. **排序可能仍然正确**（因为单调性保住了），但**分数绝对量纲是错的**；
2. 任何基于分数绝对值的下游计算——比如把分数归一化后当作置信度展示给用户——都会得出失真的结论。

如果向量库内部使用欧氏距离，需要先转换成余弦，或直接把向量库的度量方式配置为余弦空间（例如 ChromaDB 创建 collection 时指定 `metadata={"hnsw:space": "cosine"}`），而不是在做完检索后用减法手工"翻译"。

## 高维空间的直觉失效

维度升高后，向量两两之间的余弦相似度会向 0 集中，最大相似度与最小相似度的差距缩小。这被称为维度灾难的一个侧面。它意味着在高维空间中，"最相似的片段"与"第二相似的片段"分数可能非常接近，仅凭绝对阈值判断相关性并不可靠。这也是引入重排序（在候选集上做更精细的交叉编码打分）的主要动机。
